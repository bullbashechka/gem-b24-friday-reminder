==========================================================
  b24-friday-reminder — АДМИНИСТРИРОВАНИЕ СЕРВЕРА (шпаргалка)
==========================================================

Сервер:   VPS (Ubuntu/Debian), таймзона UTC
Проект:   /opt/b24-friday-reminder
Юзер:     b24bot (всё по проекту — под ним; root — только система)
Запуск:   cron, по пятницам. Скрипт разовый, без демона.


----------------------------------------------------------
1. ПОДКЛЮЧЕНИЕ
----------------------------------------------------------
ssh root@ТВОЙ_IP            # по паролю (или «Консоль» в панели хостинга)

su - b24bot                 # переключиться на пользователя проекта
cd /opt/b24-friday-reminder

exit                        # вернуться обратно в root


----------------------------------------------------------
2. РУЧНОЙ ЗАПУСК РАССЫЛКИ  (под b24bot)
----------------------------------------------------------
cd /opt/b24-friday-reminder

node src/bitrix.js                    # проверка вебхука (profile)
DRY_RUN=1 node src/index.js           # предпросмотр: кто получит, без отправки
TEST_USER_ID=30 node src/index.js     # отправить только себе (тест)
node src/index.js                     # БОЕВАЯ рассылка всем

Итоговая строка лога "Прогон завершён": sent=N failed=0 — всем ушло.


----------------------------------------------------------
3. РАСПИСАНИЕ (CRON)  (под b24bot)
----------------------------------------------------------
crontab -l                  # показать текущее расписание
crontab -e                  # редактировать (1 = nano)

Текущие строки (время в UTC, т.к. сервер в UTC; +5 = местное):
  30 4 * * 5     cd /opt/b24-friday-reminder && /usr/bin/node src/index.js >> logs/app.log 2>&1
  0 12-18 * * 5  cd /opt/b24-friday-reminder && /usr/bin/node src/index.js >> logs/app.log 2>&1

Расшифровка:
  30 4  = пятница 09:30 (один раз утром)
  0 12-18 = пятница 17:00, 18:00 ... 23:00 (каждый час)

Отключить временно: поставить # в начале строк в crontab -e.

ВАЖНО: после crontab -e перезапускать cron НЕ нужно — подхватит сам.


----------------------------------------------------------
4. СЛУЖБА CRON  (под root)
----------------------------------------------------------
systemctl status cron        # состояние
systemctl is-enabled cron    # включён ли автозапуск (должно быть enabled)
systemctl enable --now cron  # включить, если выключен
systemctl restart cron       # перезапуск (нужен редко)

Автозапуск с системой настраивать отдельно НЕ надо: cron сам стартует
после перезагрузки и выполнит расписание.


----------------------------------------------------------
5. ЛОГИ
----------------------------------------------------------
tail -f /opt/b24-friday-reminder/logs/app.log     # смотреть в реальном времени
tail -n 50 /opt/b24-friday-reminder/logs/app.log  # последние 50 строк

Логи в JSON. Ключевые поля: users, sent, failed, msg.
Читабельно: node src/index.js | npx pino-pretty


----------------------------------------------------------
6. ОБНОВЛЕНИЕ КОДА  (под b24bot)
----------------------------------------------------------
su - b24bot
cd /opt/b24-friday-reminder
git pull
npm install --omit=dev      # только если менялись зависимости

Если git ругается "dubious ownership" — значит ты под root.
Выйди (exit) и делай git ТОЛЬКО под b24bot, иначе файлы испортят владельца.

.env при git pull не трогается (его нет в репозитории).


----------------------------------------------------------
7. НАСТРОЙКИ  (.env, под b24bot)
----------------------------------------------------------
nano /opt/b24-friday-reminder/.env

  WEBHOOK_URL=...           # секретный вебхук Битрикс24
  TIMEZONE=Asia/Yekaterinburg
  DRY_RUN=                  # 1 = только лог, без отправки
  TEST_USER_ID=             # пусто = всем; число = только этому юзеру

ОПАСНО: пустой TEST_USER_ID + пустой DRY_RUN = рассылка ВСЕМ.
Перед боевым прогоном проверь:  grep -E 'DRY_RUN|TEST_USER_ID' .env


----------------------------------------------------------
8. ИЗМЕНИТЬ ТЕКСТ СООБЩЕНИЯ
----------------------------------------------------------
Текст — константа CHECKLIST в файле src/messages.js.
Правильный путь: поменять локально -> git push -> на сервере git pull.
Быстрый путь (только на сервере): nano src/messages.js, но тогда
следующий git pull может конфликтовать.


----------------------------------------------------------
9. ЛОГИКА (что важно помнить)
----------------------------------------------------------
- Пишет ТОЛЬКО тем, у кого есть ОТКРЫТАЯ задача с дедлайном СЕГОДНЯ.
- Закрытые задачи (статус 5,6,7) не считаются.
- Кто перенёс/закрыл задачу — на следующем часу уже не получит.
- "Сегодня" считается по TIMEZONE из .env, НЕ по системной зоне сервера.
- Сообщения идут от пользователя вебхука (Кирилл, ID 30).
- Лимит Битрикса ~2 req/sec — между отправками пауза 0.5с (в коде).
